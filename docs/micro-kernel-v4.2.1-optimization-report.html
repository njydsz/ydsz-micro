二、关键实现细节

2.1 P0-N1: SchedulerContext 闭包化

将 appInstances / maxKeepAliveApps / keepAliveTTL / keepAliveEnabled / keepAliveTimestamp 全部收归 SchedulerContext 对象。每个 createKernel() 创建并绑定独立上下文，消除多 Kernel 实例（测试并行 / SSR / 嵌套微前端）状态串扰。同时修复了实例级 keepAlive 永远为 false 的真实缺陷——setKeepAlive 现同时设置实例级标记，keep-alive 缓存分支首次真正可用。

// kernel.ts createKernel 闭包内
const schedulerContext = createSchedulerContext();
bindSchedulerContext(schedulerContext);
// _stop() 恢复全新上下文
bindSchedulerContext(createSchedulerContext());

2.2 P0-N2: AbortSignal 切换中止

switchToApp 引入 AbortController：快速连续切换时中止旧的 deactivate/load/mount 异步链路，避免「旧切换插花」时序问题与不必要的 unmount 开销。KernelErrorCode.SANDBOX_ERROR 首次在实际路径抛出（沙箱创建失败时）。

2.3 P1-N5: 运行时 CSS 隔离

新增 runtime-css-scope.ts：通过 CSSOM 为子应用样式表加 [data-micro-app] 前缀，覆盖「遗漏 PostCSS 配置 / :global 选择器 / 第三方构建链路」的样式泄露场景。跨域样式表自动降级保留原样；默认关闭（自有子应用已构建期 scoping），通过 config.styleIsolation 或 start({ sandbox: { styleIsolation } }) 开启。

2.4 P1-N6: 状态记忆 serialize/hydrate

LifecycleExports 扩展 serialize?() / hydrate?(state, props)：keep-alive 停用时序列化（列表滚动位置 / 表单输入），恢复激活时还原。内核在 keep-alive 摘除/复用路径自动调用。

2.5 P1-N8/N9: 接口收敛 + 隐藏 Bug 修复

修复 3 个隐藏 Bug：
  1. getApps()/prefetch() 不存在 → route prediction 预加载策略从未注册。已下沉到 kernel.start() 内置注册（N9）。
  2. setPinnedApp 未暴露 → Tab 栏 pin 调用永不生效。已补充 kernel API + 接口声明（N8）。
  3. healthCheck() 数组当 Map 用 → keepAliveCount 恒为 0。已修复 for...of + .length。

2.6 P2-N10: 懒注册 + 统一通信

kernel 新增 addApp() 运行时追加子应用（幂等）；standard-props 新增 microBridge（send/call/on），并按 action 过滤处理器。message-broker 升级为同应用多 handler（Set 语义），多个 microBridge.on 互不覆盖。

2.7 P2-N11: 沙箱按需加载

proxy/iframe 沙箱改为 await import() 动态加载，snapshot-only 场景默认包体积减小（iframe-sandbox ~23KB + proxy-sandbox ~6KB 不再进主包）。scheduler 用 strategy.type 判断替代 instanceof（类定义已动态化）。

2.8 P2-N12: i18n 显式化

error-boundary 引入 currentLocale 显式状态（替代脆弱的字符串比较），新增 setCurrentLocale() / getCurrentLocale()。同时修复 setErrorFallbackMessages 注入的自定义消息从未在 renderErrorFallback 生效的预存在 bug。

2.9 L2: SRI + CSP

Manifest.integrity.css 支持子应用构建期输出 SRI hash，loader 注入样式时附加 integrity + crossorigin="anonymous"；setCspNonce() 使动态样式标签通过 style-src 'nonce-xxx' 策略。

2.10 L3/L4: LRU 与内存

LRU 淘汰改用线性扫描（n≤20 时 O(n) 优于堆的常数开销）；KeepAlive 上限自适应——JS 堆占用 >90% 降至 1、>70% 降至 3。

五、剩余架构债务（L1）

模块级单例创建仍为 lazy getter（已纳入 dispose 管理，未闭包化）

现状：preload-strategy / version-manager / canary-manager / route-predictor 的实例创建仍为模块级 lazy 单例，_stop() 通过 ManagerRegistry 统一 dispose。多 Kernel 实例同时活跃时，这些单例仍共享。

影响评估：当前项目为单 Kernel 应用（main 全局唯一运行时），多实例场景仅存在于单元测试/SSR。scheduler 已闭包化（最核心的实例集），其余单例影响有限。

建议：若未来引入嵌套微前端或 SSR 渲染，将 4 个单例模块的创建迁移到 Kernel 闭包（与 SchedulerContext 相同模式）。当前不建议投入（风险/收益比低）。

六、下一步建议（Sprint 4+）

  2. CI/CD 落地：typecheck 门禁（当前 87 个预存在错误需逐步清零）+ 包体积预算（bundle-budget 插件已存在）

  4. 预加载 ROI 数据：通过 DevTools 性能 Tab 观察 hitRate，<5% 时降级为朴素频率模型
  5. L1 架构债：嵌套微前端 / SSR 需求出现时优先清偿
