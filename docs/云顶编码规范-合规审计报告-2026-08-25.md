## 2. 本轮新发现 · P0（门禁链路全线断裂）

> 以下五条全部经**实际运行命令**验证，非推断。

### 🔴 P0-1：`pnpm lint` 整体不可用 —— ESLint 全部强制规则失效

```
$ pnpm lint → exit 2
Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@eslint/js' imported from
  conf\lint-configs\eslint-config\dist\index.mjs
```

**根因链**（三个叠加）：

1. `conf/lint-configs/eslint-config/package.json` 的产物 `dist/index.mjs` 导入 **6 个运行时包**（`@eslint/js`、`eslint-config-prettier`、`eslint-plugin-vue`、`vue-eslint-parser`、`@typescript-eslint/eslint-plugin`、`@typescript-eslint/parser`），但该包 **dependencies 为零声明**（仅有 peerDependencies: eslint）。
2. 其中 `eslint-config-prettier` 与 `@typescript-eslint/eslint-plugin` **连 pnpm store 都不存在**——catalog 里定义了版本，但没有任何包以 `catalog:` 引用它们，即 **lockfile 缺失**。
3. 根 `package.json` 亦未声明 `eslint` 与 `@ydsz/eslint-config`，当前 eslint 9.39.5 仅靠 peer 自动安装与 public-hoist-pattern 侥幸解析——违反"绝对可控"。

**直接后果**：`no-explicit-any: error`、`no-console: error`、`vue/no-v-html: error`、`consistent-type-imports` 等全部强制条款当前**无任何工具执行**。

**修复**：

```jsonc
// conf/lint-configs/eslint-config/package.json
"dependencies": {
  "@eslint/js": "catalog:",
  "@typescript-eslint/eslint-plugin": "catalog:",
  "@typescript-eslint/parser": "catalog:",
  "eslint-config-prettier": "catalog:",
  "eslint-plugin-vue": "catalog:",
  "vue-eslint-parser": "catalog:"
}
// 根 package.json devDependencies 显式补：
"eslint": "catalog:", "@ydsz/eslint-config": "workspace:*"
```

随后 `pnpm install` → `pnpm lint`。**预期将爆出约 95 处 error**（92 处 comm/effects any + 3 处 main），需按 §3-P1-5 分批治理，勿用豁免目录压绿。

### 🔴 P0-2：`pnpm type-check` 不可用 —— turbo 任务名失配

```
$ pnpm type-check → exit 1
x Could not find task `type-check` in project
```

- 根脚本调用 `turbo type-check`，但 `turbo.json` 定义的任务名是 **`typecheck`**（无连字符）。
- 更深层：**全仓 40+ 工作区包无一定义 `typecheck` 脚本**（grep 零命中），即便任务名对齐，turbo 也无任务可跑——`conf/tsconfig/base.json` 的 strict 9 项全开（严格达标）目前没有任何执行入口。

**修复**：统一任务名为 `type-check`；在 main/apps 各包加 `"type-check": "vue-tsc --noEmit"`、comm 库包加 `"type-check": "tsc --noEmit"`（可由 `pnpm gen:app` 脚手架模板统一注入）。

### 🔴 P0-3：`pnpm test` / `pnpm build` 主链路断裂 —— 依赖构建先行失败

```
$ pnpm test → exit 1（turbo: 2 successful, 4 total → Failed: @YDSZ-core/shared#build）
ERROR Exiting with code (1). You can change this behavior by setting failOnWarn: false.
WARN Potential missing package.json files: dist/semver.d.ts, dist/semver.mjs
```

**根因**：`comm/@core/base/shared/package.json` exports 声明了 `./semver`（micro-kernel 灰度分流 3 处真实消费：`canary-manager-core.ts:15`、`canary-manager.ts:21`、`index.ts:268`），但 `build.config.ts` 的 **entries 漏配 `'src/semver'`**（现有 6 项 entries 无 semver），unbuild 3.x 默认 failOnWarn 直接 exit 1。turbo `test` 依赖 `^build`，构建中断 → **22 个测试文件一个都没跑**，`pnpm build` 同链路全红。

**修复**：`build.config.ts` entries 增加 `'src/semver'`（导出有真实消费，属漏配而非冗余）。

### 🔴 P0-4：`pnpm stylelint` 崩溃 —— 全仓 1338 个文件带 UTF-8 BOM

```
$ pnpm stylelint → exit 1
Unexpected token '﻿', "﻿{  "nam"... is not valid JSON   ← BOM 字符
```

**实测扫描（Python 按字节头 ef bb bf 检测）**：全仓 **1338 个文件带 BOM**：

| 分布 | 数量 | 分布 | 数量 |
|------|------|------|------|
| comm | 801 | conf | 47 |
| apps | 401 | bash | 15 |
| main | 66 | chrome | 6 |
| 根目录 | 2（README.md、tsconfig.paths.json） | | |

apps 8 个子应用全军覆没（各 45~58 个）；comm 重灾区 `@core/ui-kit` 360 个、`effects/layouts` 95 个、`effects/common-ui` 88 个。**含 14 个 package.json**——stylelint 的 cosmiconfig 逐级解析 package.json 时命中 BOM 即崩。

危害不止 stylelint：BOM 的 JSON 会让任何 `JSON.parse(readFileSync())` 型工具随机崩（`gen-api`、`sync-shared-deps` 等脚本同风险）；TS/Vue 文件 BOM 靠工具链宽容度苟活，属隐患。

**修复**：一次性批量剥离脚本（按字节检测去头，幂等）+ 三重防回归：`.gitattributes`、`.editorconfig`（insert_final_newline 与 charset 约束）、编辑器/脚本写文件统一 `utf-8` 无 BOM。
