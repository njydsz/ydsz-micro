> 本文档描述 YDSZ Micro 自研 **micro-kernel** 运行时在 v4.0 周期内落地的前端性能与体验优化设施。
> 所有描述均以源码事实为准，对应实现位于 `comm/effects/micro-kernel` 与 `comm/effects/monitor`。
> 关联规范见 [云顶编码规范](./云顶编码规范.md)；架构决策见 [docs/decisions/](./decisions/)。

## 1. 路由预测引擎（马尔可夫链）

**实现文件**：`comm/effects/micro-kernel/src/route-predictor.ts`（核心类 `RoutePredictor`）、
`route-predictor-core.ts`（持久化与单例）、`route-predictor-types.ts`（类型与常量）。

**模型**：一阶马尔可夫链。给定当前应用 `A`，计算转移至目标应用 `B` 的概率：

```
P(B|A) = count(A→B) / count(A→*)
```

**核心能力**：

| 能力 | 说明 | 落地版本 |
| ---- | ---- | -------- |
| 转移矩阵 | `from → (to → count)` 的稀疏 Map 存储，避免全量矩阵 | v4.0 |
| 指数衰减 | 每条转移对独立记录 `lastSeen` 时间戳，衰减基于各转移对自身年龄，近期导航权重更高 | v4.0 P0-2 (v4.2) |
| TopN 预测 | `predict(currentApp, topN=3)` 按概率降序返回预测目标 | v4.0 |
| 冷启动回退 | 当前应用无历史转移时，回退到全局高频 TopN（`getGlobalTopApps`） | v4.0 P1-4 |
| 持久化 | localStorage 跨会话保留导航模式，兼容 v1/v2 格式 | v4.0 |
| 持久化节流 | 5s 批量 flush（`schedulePersistCore`），条目上限 500 条淘汰 | v4.0 P1-1 |

**生命周期**：通过 `createRoutePredictorManager()` 纳入 `ManagerRegistry` 统一释放；`dispose()` 时先持久化转移矩阵再清理内存实例。

**单元测试**：`comm/effects/micro-kernel/src/__tests__/unit/route-predictor.spec.ts`。

## 2. 预加载策略增强

**实现文件**：`comm/effects/micro-kernel/src/preload-strategy.ts`（核心类 `PreloadManager`）、
`preload-strategy-helpers.ts`（策略工厂）、`preload-usage-stats.ts`（使用统计）、
`preload-types.ts`、`network-utils.ts`、`preload-manager-helpers.ts`。

**六种预加载策略**：

| 策略 | 触发条件 | 实现要点 |
| ---- | -------- | -------- |
| `idle` | 浏览器空闲（`requestIdleCallback`） | 空闲时段补充高频应用 |
| `hover` | 鼠标悬停 | `setupHoverListener` 监听 hover 事件 |
| `visibility` | 页面可见性变化 | `setupVisibilityListener` 监听 visibilitychange |
| `route` | 路由预测 | 接入 `RoutePredictor` 马尔可夫链预测（v4.0 P1-2） |
| `permission` | 用户权限 | `setPermissionChecker` 按权限码动态允许/拦截 |
| `frequency` | 使用频率 | `UsageStatsStore` 记录访问频次，按 `getAppsByFrequency` 排序 |

**命中率统计**（v4.0.1）：`PreloadManager.debugInfo()` 输出
`preloadCount / consumedCount / wastedCount / hitRate`，用于评估预加载收益与带宽开销。

**生命周期**：`createPreloadManager()` 纳入 `ManagerRegistry`，`dispose()` 释放 MutationObserver / visibility 监听器。

## 3. Speculation Rules 原生预取

**实现文件**：`comm/effects/micro-kernel/src/speculation-rules.ts`。

利用浏览器原生 `<script type="speculationrules">`（Chrome/Edge 108+）声明式预取子应用 ESM 模块，
在网络层提前拉取，无需等待 JS 执行。

- `isSpeculationRulesSupported()`：特性探测（Firefox/Safari 降级到 `requestIdleCallback`）。
- `buildSpeculationRules(apps, maxRules=5)`：生成 `prefetch` 规则，`eagerness: 'moderate'`（hover 200ms 后触发）。
- `applyPrefetchBoost(apps, strategy)`：联合执行器——优先 Speculation Rules，未覆盖的高频应用回退到 idle 预加载。

与 `requestIdleCallback` 预加载互补：Speculation Rules 在 HTML 解析阶段即生效、延迟极低；idle 策略可结合频率数据动态决策。

## Known Issues（已知缺口）

- `route` 预测策略的冷启动依赖历史导航数据，全新用户首会话预测收益有限（已通过全局高频回退缓解）。
- Speculation Rules 仅 Chrome/Edge 108+ 生效，Firefox/Safari 自动降级，不保证预取命中。
- 预加载命中率统计（`debugInfo`）目前仅在 DevTools 面板与日志中可读，尚未聚合上报到监控后端。
