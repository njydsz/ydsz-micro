## 1. 总则

### 1.1 规范级别定义

| 级别 | 说明 | 标识 |
|------|------|------|
| 【强制】 | 必须遵守，违反将导致 PR 拒绝 | 🔴 |
| 【推荐】 | 建议遵守，需充分理由方可偏离 | 🟡 |
| 【参考】 | 最佳实践建议，可灵活采纳 | 🟢 |

### 1.2 核心原则

1. **一致性**：同一项目内保持代码风格一致
2. **可读性**：代码是写给人看的，其次才是机器执行
3. **可维护性**：模块职责清晰，依赖关系明确
4. **类型安全**：充分利用 TypeScript 类型系统，减少运行时错误
5. **复用性**：公共能力下沉到 comm 模块，避免重复实现

## 2. 命名规范

### 2.1 文件命名

> **【强制】** 文件命名遵循以下规则：

| 文件类型 | 命名规则 | 示例 |
|---------|---------|------|
| Vue 组件 | PascalCase | `UserProfile.vue`、`AppHeader.vue` |
| composables | use + 功能名（camelCase） | `useAuth.ts`、`usePagination.ts` |
| store 模块 | 功能名（camelCase） | `auth.ts`、`notification.ts` |
| 工具函数 | camelCase | `dateUtils.ts`、`formatHelper.ts` |
| 类型文件 | 功能名 + `.d.ts` 或 `types.ts` | `user.d.ts`、`api-types.ts` |
| 常量文件 | camelCase 或 SCREAMING_SNAKE_CASE | `core.ts`、`API_ENDPOINTS.ts` |
| 样式文件 | 与组件同名 | `UserProfile.scss` |
| 测试文件 | 被测文件名 + `.test.ts` / `.spec.ts` | `auth.test.ts`、`useAuth.spec.ts` |

### 2.2 目录命名

> **【强制】** 目录命名遵循以下规则：

| 场景 | 规则 | 示例 |
|------|------|------|
| 普通目录 | kebab-case | `user-info/`、`common-ui/` |
| 复数资源 | 复数形式 | `components/`、`composables/`、`views/` |
| 缩写目录 | 全小写 | `api/`、`utils/`、`hooks/` |

### 2.3 变量与函数命名

> **【强制】** 变量和函数使用 camelCase 命名，必须见名知意。

```typescript
// ✅ 正确
const userName = 'John';
const isLoading = false;
function fetchUserData() {}
function handleSubmit() {}

// ❌ 错误
const u = 'John';
const flag = false;
function getData() {}
function click() {}
```

### 2.4 常量命名

> **【强制】** 常量使用 SCREAMING_SNAKE_CASE 命名。

```typescript
// ✅ 正确
const MAX_RETRY_COUNT = 3;
const DEFAULT_PAGE_SIZE = 20;
const API_BASE_URL = '/api/v1';

// ❌ 错误
const maxRetryCount = 3;
const defaultPageSize = 20;
```

### 2.5 类型与接口命名

> **【推荐】** 类型使用 PascalCase 命名，接口可加 `I` 前缀或不加（项目内统一）。

```typescript
// ✅ 正确（本项目风格：接口不加 I 前缀）
interface UserInfo {
  id: number;
  name: string;
  email: string;
}

interface BaseResponse<T = unknown> {
  code: string;
  msg: string;
  data: T;
}

// 类型别名同样 PascalCode
type RequestConfig = {
  baseURL?: string;
  timeout?: number;
};
```

### 2.6 CSS 类名命名

> **【强制】** CSS 类名使用 BEM 命名规范或 Tailwind CSS 原子类。

```scss
// BEM 命名（自定义样式场景）
.user-card {           // Block
  &__header {          // Element
    padding: 16px;
  }
  &--active {          // Modifier
    border-color: #1890ff;
  }
}
```

## 3. TypeScript 规范

### 3.1 类型声明

> **【强制】** 禁止使用 `any` 类型，必须显式声明类型。特殊情况需添加注释说明理由。

```typescript
// ✅ 正确
function getUser(id: number): Promise<UserInfo> {
  return request.get(`/users/${id}`);
}

// ❌ 错误
function getUser(id: any): any {
  return request.get(`/users/${id}`);
}

// ⚠️ 特殊场景（需注释说明）
function parseResponse(resp: unknown): UserInfo {
  // 外部数据来源不可控，需运行时校验
  return resp as UserInfo;
}
```

### 3.2 接口与类型别名选择

> **【推荐】** 优先使用 `interface` 定义对象类型，`type` 用于联合类型、交叉类型、函数类型等场景。

```typescript
// ✅ 对象类型用 interface
interface UserInfo {
  id: number;
  name: string;
}

// ✅ 联合类型用 type
type Status = 'pending' | 'success' | 'error';

// ✅ 函数类型用 type
type RequestHandler = (config: RequestConfig) => RequestConfig;
```

### 3.3 泛型使用

> **【推荐】** 通用工具函数和组件应使用泛型提升复用性。

```typescript
// ✅ 泛型函数
function filterList<T>(list: T[], predicate: (item: T) => boolean): T[] {
  return list.filter(predicate);
}

// 泛型响应类型
interface ApiResponse<T = unknown> {
  code: string;
  data: T;
  message: string;
}
```

### 3.4 严格模式

> **【强制】** 项目启用 TypeScript 严格模式（`strict: true`），禁止关闭以下选项：

```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "strictFunctionTypes": true,
    "strictBindCallApply": true,
    "noImplicitThis": true,
    "alwaysStrict": true
  }
}
```

### 3.5 模块导入导出

> **【强制】** 导入导出遵循以下规则：

```typescript
// ✅ 正确：类型导入使用 type 关键字
import type { UserInfo } from '@ydsz/types';
import { ref, computed } from 'vue';

// ✅ 正确：路径别名使用项目配置的别名
import { useAuthStore } from '#/store/auth';
import { requestClient } from '#/api/request';

// ❌ 错误：混用类型和值导入（未区分 type）
import { UserInfo, useAuthStore } from './types';
```

### 3.6 可选链与空值合并

> **【推荐】** 优先使用可选链 `?.` 和空值合并 `??` 处理空值。

```typescript
// ✅ 正确
const userName = user?.profile?.name ?? 'Unknown';
const total = data?.list?.length ?? 0;

// ❌ 错误：冗长的空值判断
const userName = user && user.profile && user.profile.name ? user.profile.name : 'Unknown';
```

## 4. Vue 组件规范

### 4.1 组件结构

> **【强制】** Vue 单文件组件遵循 `<script setup>` 优先原则，结构顺序为：`<script setup>` → `<template>` → `<style>`。

```vue
<script setup lang="ts">
// 1. 导入语句
import { ref, computed, onMounted } from 'vue';
import type { PropType } from 'vue';

// 2. 类型定义
interface UserInfo {
  id: number;
  name: string;
}

// 3. Props 定义
const props = defineProps({
  user: {
    type: Object as PropType<UserInfo>,
    required: true,
  },
});

// 4. Emits 定义
const emit = defineEmits<{
  (e: 'update', value: string): void;
  (e: 'delete', id: number): void;
}>();

// 5. 响应式数据
const isLoading = ref(false);
const searchText = ref('');

// 6. 计算属性
const displayName = computed(() => props.user.name || 'Unknown');

// 7. 方法
function handleClick() {
  emit('update', searchText.value);
}

// 8. 生命周期
onMounted(() => {
  // 初始化逻辑
});
</script>

<template>
  <div class="user-card">
    <h3>{{ displayName }}</h3>
    <button @click="handleClick">更新</button>
  </div>
</template>

<style scoped lang="scss>
.user-card {
  padding: 16px;
}
</style>
```

### 4.2 Props 定义

> **【强制】** Props 必须使用 TypeScript 类型声明，禁止使用简单的数组或对象形式。

```typescript
// ✅ 正确：使用泛型定义
interface Props {
  title: string;
  count?: number;
  status?: 'active' | 'inactive';
}

const props = withDefaults(defineProps<Props>(), {
  count: 0,
  status: 'active',
});

// ❌ 错误：简单对象形式
const props = defineProps({
  title: String,
  count: Number,
});
```

### 4.3 事件命名

> **【强制】** 事件名称使用 camelCase，模板中使用 kebab-case。

```typescript
// ✅ 正确
const emit = defineEmits<{
  (e: 'item-click', item: Item): void;
  (e: 'status-change', status: string): void;
}>();

// 模板中使用
<MyComponent @item-click="handleClick" @status-change="handleStatusChange" />
```

### 4.4 组件命名

> **【强制】** 组件文件名和组件名使用 PascalCase。

```vue
<!-- ✅ 正确 -->
<!-- 文件：UserProfile.vue -->
<script setup lang="ts">
defineOptions({ name: 'UserProfile' });
</script>

<!-- ❌ 错误 -->
<!-- 文件：user-profile.vue -->
<script setup lang="ts">
defineOptions({ name: 'userProfile' });
</script>
```

### 4.5 组件职责

> **【推荐】** 单一职责原则：一个组件只负责一个功能，超过 300 行应考虑拆分。

| 组件类型 | 职责 | 示例 |
|---------|------|------|
| 视图组件（views） | 页面级组件，负责页面布局 | `DashboardView.vue` |
| 业务组件（components） | 可复用的业务逻辑组件 | `UserSelector.vue` |
| 基础组件（ui-kit） | 纯 UI 组件，无业务逻辑 | `BaseButton.vue`、`BaseInput.vue` |

### 4.6 v-for 与 key

> **【强制】** `v-for` 必须绑定 `:key`，禁止使用索引作为 key。

```vue
<!-- ✅ 正确 -->
<UserCard v-for="user in userList" :key="user.id" :user="user" />

<!-- ❌ 错误 -->
<UserCard v-for="(user, index) in userList" :key="index" :user="user" />
```

### 4.7 条件渲染

> **【推荐】** 使用 `v-if` / `v-else-if` / `v-else` 进行条件渲染，避免 `v-show` 滥用。

```vue
<!-- ✅ 正确：频繁切换用 v-show -->
<div v-show="isVisible">频繁显示/隐藏的内容</div>

<!-- ✅ 正确：条件渲染用 v-if -->
<LoadingSpinner v-if="isLoading" />
<ErrorState v-else-if="hasError" />
<UserList v-else :users="users" />
```

### 4.8 插槽使用

> **【推荐】** 具名插槽使用模板语法，作用域插槽使用解构。

```vue
<!-- ✅ 正确 -->
<template #header>
  <h2>标题</h2>
</template>

<template #default="{ item, index }">
  <span>{{ index }}: {{ item.name }}</span>
</template>
```

## 5. API 请求规范

### 5.1 请求客户端使用

> **【强制】** 统一使用 `@ydsz/request` 提供的请求客户端，禁止直接使用 `axios` 或 `fetch`。

```typescript
// ✅ 正确：使用共享请求客户端
import { requestClient, baseRequestClient } from '#/api/request';

// 带鉴权的请求
const userData = await requestClient.get<UserInfo>('/api/user/profile');

// 公共接口请求（登录、刷新令牌等）
const loginResp = await baseRequestClient.post<LoginResponse>('/api/auth/login', loginForm);
```

### 5.2 API 模块组织

> **【强制】** API 接口按业务模块组织，每个模块一个文件。

```
api/
├── index.ts          # 导出入口
├── request.ts        # 请求客户端配置
└── core/
    ├── index.ts      # 模块导出
    ├── auth.ts       # 认证相关接口
    ├── user.ts       # 用户相关接口
    └── dashboard.ts  # 仪表盘相关接口
```

### 5.3 接口定义规范

> **【强制】** API 函数必须定义参数类型和返回类型，使用项目统一的 `BaseResponse<T>` 类型。

```typescript
// ✅ 正确
import type { BaseResponse, PageResponse, PageQuery } from '@ydsz/types';

/** 获取用户信息 */
export function getUserInfo(): Promise<BaseResponse<UserInfo>> {
  return requestClient.get('/api/user/info');
}

/** 分页查询用户列表 */
export function queryUserList(params: PageQuery & { keyword?: string }): Promise<PageResponse<UserInfo>> {
  return requestClient.get('/api/user/list', { params });
}

/** 创建用户 */
export function createUser(data: CreateUserDto): Promise<BaseResponse<number>> {
  return requestClient.post('/api/user', data);
}
```

### 5.4 错误处理

> **【强制】** 业务层错误统一由请求拦截器处理，组件层只需处理 UI 交互。

```typescript
// ✅ 正确：组件层处理
async function handleSubmit() {
  try {
    loading.value = true;
    const userId = await createUser(formData);
    // 成功提示由拦截器统一处理，这里只需处理业务逻辑
    router.push(`/users/${userId}`);
  } catch (error) {
    // 错误提示由拦截器统一处理，这里只处理特殊场景
    console.error('创建用户失败:', error);
  } finally {
    loading.value = false;
  }
}
```

### 5.5 请求取消

> **【推荐】** 页面切换时自动取消未完成的请求，使用 `AbortController` 或请求库内置机制。

```typescript
// ✅ 正确：使用请求库内置的取消机制
const controller = new AbortController();

fetchData({ signal: controller.signal });

// 页面卸载时取消
onUnmounted(() => {
  controller.abort();
});
```

## 6. 状态管理规范

### 6.1 Store 类型

> **【强制】** 使用 Pinia 的 Composition API 风格（`setup` 语法），禁止使用 Options API 风格。

```typescript
// ✅ 正确：setup 语法
export const useAuthStore = defineStore('auth', () => {
  // 状态
  const userInfo = ref<UserInfo | null>(null);
  const token = ref<string | null>(null);

  // 计算属性
  const isLoggedIn = computed(() => !!token.value);

  // 方法
  function setToken(newToken: string | null) {
    token.value = newToken;
  }

  async function login(credentials: LoginDto) {
    const resp = await loginApi(credentials);
    token.value = resp.data.token;
    userInfo.value = resp.data.userInfo;
  }

  function logout() {
    token.value = null;
    userInfo.value = null;
  }

  return { userInfo, token, isLoggedIn, setToken, login, logout };
});
```

### 6.2 Store 模块组织

> **【强制】** Store 按业务模块组织，每个模块一个文件。

```
store/
├── index.ts          # 导出入口
├── auth.ts           # 认证状态
├── notification.ts   # 通知状态
└── ...
```

### 6.3 共享状态

> **【强制】** 跨应用共享状态统一放在 `comm/stores` 模块，禁止在子应用中重复定义。

```typescript
// ✅ 正确：使用共享 store
import { useAuthStore, useAccessStore } from '@ydsz/stores';

const authStore = useAuthStore();
const accessStore = useAccessStore();
```

### 6.4 状态持久化

> **【推荐】** 需要持久化的状态使用 `pinia-plugin-persistedstate`，避免手动操作 localStorage。

```typescript
export const useAppConfigStore = defineStore('appConfig', () => {
  // ...
}, {
  persist: {
    key: 'app-config',
    storage: localStorage,
    paths: ['theme', 'language'],
  },
});
```

## 7. 路由规范

### 7.1 路由配置

> **【强制】** 路由配置按业务模块组织，使用懒加载。

```typescript
// ✅ 正确
const routes: RouteRecordRaw[] = [
  {
    path: '/dashboard',
    component: () => import('#/views/dashboard/index.vue'),
    meta: {
      title: '仪表盘',
      icon: 'dashboard',
    },
  },
];
```

### 7.2 路由元信息

> **【强制】** 路由元信息必须包含 `title`，按需添加其他属性。

```typescript
interface RouteMeta {
  /** 页面标题（必填） */
  title: string;
  /** 菜单图标 */
  icon?: string;
  /** 是否隐藏菜单 */
  hideInMenu?: boolean;
  /** 权限标识 */
  permission?: string;
  /** 是否缓存 */
  keepAlive?: boolean;
  /** 是否外链 */
  external?: boolean;
  /** 外链地址 */
  externalUrl?: string;
}
```

### 7.3 路由守卫

> **【强制】** 路由守卫统一在 `router/guard.ts` 中配置，禁止在组件内重复实现权限校验逻辑。

```typescript
// ✅ 正确：统一守卫
router.beforeEach(async (to, from, next) => {
  const authStore = useAuthStore();
  
  if (to.meta.permission && !authStore.hasPermission(to.meta.permission)) {
    next({ name: 'Forbidden' });
    return;
  }
  
  next();
});
```

## 8. 样式规范

### 8.1 Tailwind CSS 优先

> **【强制】** 优先使用 Tailwind CSS 原子类，减少自定义 CSS。

```vue
<!-- ✅ 正确：使用 Tailwind -->
<div class="flex items-center justify-between p-4 bg-white rounded-lg shadow">
  <h2 class="text-lg font-semibold text-gray-800">标题</h2>
</div>

<!-- ❌ 错误：大量自定义 CSS -->
<div class="custom-card">
  <h2 class="custom-title">标题</h2>
</div>
```

### 8.2 CSS 变量

> **【强制】** 主题色、间距等设计 Token 使用 CSS 变量，定义在 `comm/@core/base/design/` 中。

```css
:root {
  --color-primary: #1890ff;
  --color-success: #52c41a;
  --color-warning: #faad14;
  --color-error: #ff4d4f;
  --spacing-xs: 4px;
  --spacing-sm: 8px;
  --spacing-md: 16px;
  --spacing-lg: 24px;
}
```

### 8.3 响应式设计

> **【推荐】** 使用 Tailwind 的响应式前缀处理不同屏幕尺寸。

```vue
<!-- ✅ 正确 -->
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-4">
  <!-- 内容 -->
</div>
```

### 8.4 Scoped 样式

> **【强制】** 组件样式必须使用 `scoped` 或 CSS Modules，避免样式污染。

```vue
<!-- ✅ 正确 -->
<style scoped>
.user-card {
  padding: 16px;
}
</style>

<!-- ✅ 正确：CSS Modules -->
<style module>
.userCard {
  padding: 16px;
}
</style>
```

### 8.5 SCSS 使用

> **【推荐】** 使用 SCSS 编写复杂样式，保持嵌套层级不超过 3 层。

```scss
// ✅ 正确
.user-card {
  padding: 16px;
  
  &__header {
    display: flex;
    align-items: center;
    
    .avatar {
      width: 40px;
      height: 40px;
    }
  }
}

// ❌ 错误：嵌套过深
.user-card {
  .header {
    .info {
      .name {
        .text {
          color: red;
        }
      }
    }
  }
}
```

## 9. 微前端规范

### 9.1 主应用职责

> **【强制】** 主应用（main）负责：
> - 用户认证与权限管理
> - 全局导航与路由管理
> - 公共组件与状态提供
> - 子应用注册与生命周期管理

### 9.2 子应用规范

> **【强制】** 子应用必须：
> - 导出标准的 `bootstrap`、`mount`、`unmount` 生命周期
> - 使用 `@ydsz/micro-runtime` 提供的 API 与主应用通信
> - 独立构建部署，不依赖主应用运行时

```typescript
// ✅ 正确：子应用入口
import { defineSubApp } from '@ydsz/micro-runtime';
import { createApp } from 'vue';
import App from './app.vue';

export default defineSubApp({
  async bootstrap() {
    // 初始化逻辑
  },
  async mount(container) {
    const app = createApp(App);
    app.mount(container);
    return app;
  },
  async unmount(app) {
    app?.unmount();
  },
});
```

### 9.3 通信规范

> **【强制】** 主应用与子应用通信使用 `message-broker`，禁止直接访问对方状态。

```typescript
// ✅ 正确：使用消息代理
import { useMessageBroker } from '@ydsz/micro-kernel';

const broker = useMessageBroker();

// 发送消息
broker.emit('user:updated', { userId: 1 });

// 监听消息
broker.on('user:updated', (data) => {
  console.log('用户更新:', data);
});
```

### 9.4 样式隔离

> **【强制】** 子应用必须启用 CSS 隔离，使用 `css-containment` 或 Shadow DOM。

```typescript
// ✅ 正确：启用样式隔离
import { enableCssContainment } from '@ydsz/micro-kernel';

enableCssContainment({
  scope: 'sub-app-name',
  strategy: 'css-scope', // 或 'shadow-dom'
});
```

### 9.5 子应用独立开发

> **【推荐】** 子应用应支持独立开发模式，不依赖主应用运行。

```typescript
// ✅ 正确：独立开发模式判断
if (import.meta.env.MODE === 'development' && !window.__MICRO_KERNEL__) {
  // 独立运行模式，初始化 mock 数据
  await import('./mock');
}
```

## 11. 错误处理与监控规范

### 11.1 错误边界

> **【强制】** 使用 `ErrorBoundary` 组件捕获子组件错误，避免整个应用崩溃。

```vue
<!-- ✅ 正确 -->
<ErrorBoundary @error="handleError">
  <UserList />
</ErrorBoundary>
```

### 11.2 错误上报

> **【强制】** 全局错误统一上报到监控系统（Sentry），使用 `@ydsz/monitor` 模块。

```typescript
// ✅ 正确：使用统一监控
import { captureException, captureMessage } from '@ydsz/monitor';

try {
  await fetchData();
} catch (error) {
  captureException(error, { context: 'fetchData' });
}
```

### 11.3 用户反馈

> **【推荐】** 关键操作失败时提供明确的用户反馈，避免静默失败。

```typescript
// ✅ 正确
async function handleDelete(id: number) {
  const confirmed = await confirmDialog('确认删除该用户？');
  if (!confirmed) return;
  
  try {
    await deleteUser(id);
    message.success('删除成功');
  } catch (error) {
    message.error('删除失败，请稍后重试');
  }
}
```

### 11.4 性能监控

> **【推荐】** 使用 `@ydsz/monitor` 提供的性能追踪能力，监控关键操作耗时。

```typescript
import { withPerformanceTracking } from '@ydsz/monitor';

// ✅ 正确
const fetchDashboardData = withPerformanceTracking(
  async () => {
    const data = await dashboardApi.getData();
    return data;
  },
  'dashboard-data-fetch'
);
```

## 12. 构建与依赖管理

### 12.1 包管理器

> **【强制】** 使用 `pnpm` 作为包管理器，禁止使用 `npm` 或 `yarn`。

### 12.2 依赖版本

> **【强制】** 依赖版本遵循以下规则：

| 规则 | 说明 |
|------|------|
| 版本锁定 | 提交 `pnpm-lock.yaml`，确保团队成员依赖一致 |
| 版本范围 | 使用 `^` 前缀允许补丁版本更新 |
| 安全更新 | 定期执行 `pnpm audit` 检查安全漏洞 |

### 12.3 模块导入

> **【强制】** 使用项目配置的路径别名，避免相对路径过深。

```typescript
// ✅ 正确：使用路径别名
import { useAuthStore } from '#/store/auth';
import { requestClient } from '#/api/request';
import { useI18n } from '@ydsz/locales';

// ❌ 错误：过深的相对路径
import { useAuthStore } from '../../../comm/stores/src/modules/auth';
```

### 12.4 构建配置

> **【强制】** 构建配置统一在 `conf/vite-config` 中管理，禁止在子应用中覆盖全局配置。

### 12.5 代码检查

> **【强制】** 提交前必须通过以下检查：

```bash
# ESLint 检查
pnpm lint

# TypeScript 类型检查
pnpm type-check

# 样式检查
pnpm stylelint

# 单元测试
pnpm test
```

### 12.6 提交规范

> **【强制】** 提交信息遵循 Conventional Commits 规范：

```
<type>(<scope>): <description>

[optional body]

[optional footer]
```

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复 bug |
| docs | 文档变更 |
| style | 代码格式（不影响功能） |

## 13. 代码审查清单

### 13.1 Pre-PR 自查清单

提交 PR 前，开发者应逐项确认：

- [ ] 代码通过 ESLint 检查（`pnpm lint`）
- [ ] 代码通过 TypeScript 类型检查（`pnpm type-check`）
- [ ] 无 `any` 类型（特殊情况已注释说明）
- [ ] 组件使用 `<script setup>` 语法
- [ ] Props 和 Emits 使用 TypeScript 类型声明
- [ ] API 请求使用统一的请求客户端
- [ ] 错误处理完善，无静默失败
- [ ] 国际化文本使用 `t()` 函数
- [ ] 样式使用 Tailwind 优先
- [ ] 无重复代码，公共能力已下沉到 comm 模块
- [ ] 提交信息符合 Conventional Commits 规范

### 13.2 审查关注点

| 关注点 | 说明 |
|--------|------|
| 类型安全 | 检查是否有 `any` 滥用、类型断言是否合理 |
| 组件设计 | 职责是否单一、是否可复用 |
| 性能 | 是否有不必要的重复渲染、大数据是否使用虚拟滚动 |
| 安全 | XSS 防护、敏感信息是否暴露 |
| 可访问性 | 键盘导航、屏幕阅读器支持 |
